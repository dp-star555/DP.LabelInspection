# 异常检测以不可变模型资产连接训练与可替换运行实现

用户要求在HALCON、Anomalib导出模型及其它算法之间快速切换，不重写标签节点、采集和报告。拟将异常检测的公开接口从具体Patch浮点模型提升到“实现登记—模型资产—加载实例—中立测量结果”，并将可选训练能力与必需推理能力分开：Anomalib是训练框架，ONNX Runtime/OpenVINO是部署方式，不能把它们与HALCON品牌简单视为同一类对象。

不采用“把HALCON句柄或字节伪装成PatchAnomalyModel”的方式，也不要求纯推理实现提供假的Train方法。保留现有Patch接口及旧库读取，通过旧模型Adapter进入新入口；HALCON原生对象只存在于厂商实现内部。

代价是模型格式、加载缓存和工作台选择必须一起改造，不能只新增一个检测类。切换必须同时选择兼容模型资产及已验证的预处理/阈值；不自动跨厂商转换、不回退旧模型、不改变在途快照。完整设计及迁移验收见[多实现异常检测设计](../anomaly-provider-architecture.md)。本决定是待实施设计，不表示HALCON或Anomalib已接入。
