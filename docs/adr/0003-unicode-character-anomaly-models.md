# 逐字符异常模型使用Unicode身份与显式行归一化

## 状态
已实现，补充ADR-0001的参考字库能力；不是将A字库自动转换成B模型。

## 背景
通用单字候选可含中文、标点、符号及补充平面字符，但B的模型键、覆盖统计、训练和正式检测曾只支持ASCII。只去掉键校验会继续跳过字符；依赖字母/数字测量行高又无法处理纯标点，按残余墨迹单字缩放则可能掩盖缺笔。

## 决定
- 共用`CharacterIdentity.IsGlyph`精确Unicode标量身份，保持大小写、全半角、顺序及代理对。空白、控制/格式字符、组合序列不是独立单字。
- 模型键仍为`字符组/单字`或单字。按最后一个Unicode标量解析，`/`本身也是合法单字（例如`组//`），不把补充平面拆成两半；已有ASCII键字节不变。
- 制作会话传递明确行ROI。新B模型采用`LineRegion`稳定行ROI几何，字体、行高与ROI边距属于训练组条件；不随当前墨迹收缩放大、不猜测行ROI、不引入det。
- 不提供ROI的历史调用保留`LineInk`方式；旧ASCII模型缺字段时默认历史方式。同键训练不能混用两种几何。归一化方式贯穿训练结果、运行参考、阈值修正、导入导出及正式检测。
- 新Unicode或ROI模型文档为`dp.labelinspection.anomaly-library.v2`，新版同时读v1/v2。旧SDK拒读v2，不能忽略新模式后错误比较。内容寻址模型字节、历史修订与原子发布保留，不覆盖旧修订。
- 可靠Unicode分割可直接选入，表格可编辑单字；不增加人工确认勾选。不可靠分割默认未选，原有问题提示保留。未训练组不生成新绑定，缺中文/标点模型仍NG，不批准半行覆盖。
- `.NET48`原子写入临时文件使用同目录短GUID名，而非`SHA.bin.GUID.tmp`，避免目标路径在MAX_PATH内但临时路径超长；同卷原子移动、CreateNew、Flush及失败清理保持。不支持任意超长资源根，也不放宽路径安全检查。

## 代价
新训练组需要一致的行ROI边距和字体尺寸；不同字体/尺度应分组重训，不能用扩大/压缩ROI掩盖缺陷。旧模型继续沿用历史几何，不自动迁移。A/B仍独立，各自需要实际良品资产。

## 验证
- 中文真实字体fixture：`中文标签：100，合格。`，4来源训练11种身份，正式B检查全部12字；冒号上点缺失NG，缺中文模型NG。
- 合成纯标点、斜杠及补充平面身份实际训练/检测，点缺墨NG；键往返、非法身份、覆盖、导入导出、未知模式及历史缺字段兼容。
- `.NET48`长路径保存测试先复现DirectoryNotFoundException，再验证短临时名发布成功且无残留。
- net8/net48原生窗口使用官方V6和真实OpenCV：4张良品提取、实际训练按钮发布11模型，正式B检测12/12通过。

这些是合成/原生流程验证，不代表工业精度、现场样张或长期内存压力验收。
