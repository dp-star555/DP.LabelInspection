# ADR-0002：同图多ROI制作与候选归属隔离

- 状态：接受

## 背景

原生多图制库原来只有一个可变ROI、文字框和提取结果。再次框行/提取会清空整张图候选，导致同图多个文字行无法累计。来源图与跨图暂存已有独立像素语义，不能用“全部追加”解决重提重复，也不能根据几何相交删除旧行：制作ROI可能交叠。

## 决策

- Core引入不可变`GlyphDraftRegion`记录，由`GlyphDraftSession`登记当前图的独立单行ROI：稳定ID、序号名称、原图范围、人工文字、最近提取证据及失败状态。不是正式配方ROI，不训练整行模板。
- `GlyphDraftCandidate.RegionId`显式归属。新ROI成功提取累计候选；重提仅替换同ID候选。其他ROI人工标签和候选ID不变。手工补框可显式附属于选中区域，独立裁图为null；改框/切分保留归属。
- 原始OCR读数与人工文字不混用。界面按选中区域恢复文字/证据；批量按区域人工文字或OCR串行调用原服务，不引入多行det链路或并行调用同一模型。
- 失败、零候选及取消保留旧候选并记录状态；批量非取消异常继续下一ROI。取消在异步返回后再次检查，不发布忽略取消的迟到结果，也不撤销已经完成的其他行。保留旧候选不表示本次成功，更不认证良品。
- ROI新增/删除/调整、文字和候选编辑共同进入20步撤销/重做。调整范围清除同ROI旧证据/候选，撤销共同恢复。用户选定暂存的独立快照不随编辑、取消或撤销改变。
- 识别后直接编辑表格单字并选择加入清单，不要求先输入整行文字或另勾“已核对字符”。整行人工纠错仍为可选重分割入口；新追溯仅记录`user_selected`，不自动宣称人工认证，历史追溯不改写。WorkFlow在仅装配字库、尚未载入主配置图时也连接编辑提取引擎，服务绑定立即更新所有提取按钮。
- 表格显示来源ROI；暂存来源名及发布追溯包含制作ROI名称/ID。来源仅用于追溯，不限制未来字符组合，不自动绑定配方。
- 换图清除当前ROI、候选及历史。（修订：已取消跨图待入库清单，勾选候选后直接“保存选中到字库”，每次保存发布一个新修订；草稿会话的暂存只在单次保存内使用，失败即清空。）每图最多32个水平单行ROI；每次单行提取最多128候选；当前图最多4096候选/1600万候选像素，单次保存/字库仍使用已有4096参考/1600万参考像素预算。这不是进程字节硬限，撤销历史和模型另占内存。

## 验证

- 原生窗口先复现：第二ROI提取后只有B，未保留A；修复后同图A/B保留。
- Core回归覆盖交叠区域隔离、独立替换、文字、手工切分归属、几何撤销、失败保留、跨图暂存和预算。
- WorkFlow原生STA窗口测试覆盖实际OpenCV逐条提取、勾选/标签保留、批量失败继续、各行人工文字、取消/忙保护、跨图发布和重复标签选择来源。
- 官方V6实际OCR/OpenCV分割/原生发布/正式规则质量冒烟：同图3个中文标点ROI，每行12字符，共36字符；重提中间ROI不改变其他ROI。合成同字体检查不代表现场复杂标签和工业精度验收。
