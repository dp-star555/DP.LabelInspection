# 03 · 待封装项、实施顺序与验收清单

> 以下未勾选项均为后续工作，不代表本轮已经实现。目标是把现有成熟操作链路交付成容易使用的节点，而不是重新开发检测算法。

## 1. 缺口清单

| 编号 | 缺口 | 优先级 | 完成标准 |
|---|---|---|---|
| G01 | 专用节点模型/Handler/注册 | P0 | 工具箱只有一个标签检测入口，能够绑定图像并无界面运行 |
| G02 | 配方与参考/字库/模型的部署资源关系 | P0 | 配置能迁移到干净机器；缺资源明确诊断，不找开发目录、不升级修订 |
| G03 | 宿主运行能力装配与生命周期 | P0 | 无UI运行可用，模型复用；取消/退出后有序释放，所有权明确 |
| G04 | 输出与完成性语义 | P0 | 完整报告和真实Verdict可读；业务NG、未完成和程序故障不混淆；不推测全局完成布尔值 |
| G05 | 工作台配置捕获/装载/提交桥 | P0 | 不遗漏Options/Bindings/Tasks/参考模式等；编辑取消不改正式节点，配方身份不丢失 |

## 2. 推荐实施顺序

### 第一阶段：锁定节点边界与最小无UI链路

- [ ] 专用节点模型，不继承通用分析ROI模型来隐式取得不支持的范围能力。
- [ ] 上游DP.Vision.ImageFrame绑定、固定配方/参考解析、可选TaskData及CycleId。
- [ ] 通过宿主能力调用现有引擎，不修改RoiWorkflow。
- [ ] 输出完整报告与输入FrameId/配置身份；先保留诊断语义，再提供经过定义的便捷摘要。
- [ ] 能力注册与运行前预检；OCR需求随已选任务，不强制空白节点装载无关模型。

**交付门槛：**没有任何窗体也能运行已有标签样例并获得同语义报告。

### 第二阶段：完整配置体验与可靠保存

- [ ] 确定配置资源包/资源仓引用方案，加入固定版本及校验。
- [ ] WinForms工作台编辑隔离草稿，接上节点确认/取消流程。
- [ ] 配方名称、尺寸、模式、对齐、区域、Field、Tasks、Options、Bindings完整往返。
- [ ] 作者样张、参考图和动态调试数据分别处理；不能把上一次生产输入保存成下一次隐式默认。
- [ ] 明确字库发布是外部持久化操作，不因节点取消而假装撤回。
- [ ] 从Demo宿主提取模型装配、配方I/O、必要作者工具入口及退出等待。

**交付门槛：**新用户在节点页完成配置，保存流程、关闭重开后，无需Demo专用代码也能执行。

### 第三阶段：结果查看、双UI与生产部署

- [ ] 结果页读取正确执行身份下的报告，而非NodeId对应的任意最新结果。
- [ ] 原图/参考/局部证据分别生成VisionView，保留各自坐标。
- [ ] 补齐并验证WPF功能矩阵；必须原生渲染。
- [ ] 可选报告保存、历史和导出；失败不篡改已有测量证据。
- [ ] 资源及报告预算、并发/停止行为、模型替换和配置版本切换。
- [ ] 干净机器部署检查及最小示例，不携带私有生产资产。

## 3. 验收用例

### 配置与资源

- [ ] 包含文字、1D、QR、Fixed、Blank、Ignore的现有合法配方完整往返。
- [ ] 只做空白检查不新增OCR强依赖；选中读取/质量所需能力缺失不能静默关闭项目。
- [ ] 缺参考图、尺寸不符、缺固定字库修订、模型哈希不符均明确处理。
- [ ] 导入字库的新ID与配方绑定建立显式映射，不偷偷取Latest。
- [ ] 取消编辑、撤销/重做、打开不修改文档；另行发布字库的副作用有明确提示。
- [ ] 清理开发模型路径和样例目录后，节点仍按部署清单运行或明确报告缺失。
- [ ] Workflow配置快照/JSON不会序列化活动帧、控件、引擎或上次运行数据。

### 检测与输出

- [ ] 同输入、同配置、同资源，节点与现有SDK的实际读值、Verdict、阶段和证据一致。
- [ ] 内容不符不重写读值；识别成功不自动通过质量；全部忽略/空ROI不放行。
- [ ] 一个ROI失败仍处理其他独立ROI，依赖区域按现有规则阻断。
- [ ] 真实缺陷导致的阶段Failed与资源/执行问题导致的Failed可区分，不以异常与否替代覆盖判断。
- [ ] Report.Verdict=Ng不会自动触发设备重试；Review不被丢失或伪装为Ok。
- [ ] 任务数据缺失、过期、未来时间和CycleId不匹配不复用上一帧数据。
- [ ] 多码/歧义读取保留原候选与诊断，不挑第一项生成假唯一读值。
- [ ] 节点循环、并行作用域、同一节点重复执行的结果身份正确。
- [ ] 通用输出序列化、数值NaN、报告中的字符图块和下游字段绑定均经过实际验证。

### 生命周期、界面与存储

- [ ] 排队前输入保留；成功、异常、取消、关闭和重跑均释放自己拥有的资源。
- [ ] 原生工作未退出时不释放模型；共享引擎串行行为可预测，不出现UI同步等待死锁。
- [ ] 配置页试运行不向生产流程发布标准输出；外部停止可取消试运行并等待清理。
- [ ] 图层切换不执行检测，切视图不显示其他图像的叠加，参考偏移与局部图坐标正确。
- [ ] 无图/迟到预览/预览淘汰不复用旧图，也不改变报告。
- [ ] 报告写入失败、磁盘不足、退出等待及重试保存策略明确；不重复检测来补存报告。
- [ ] 长时间循环的报告、字符/差异图、输入帧和显示缓存分别满足约定预算。
- [ ] 用户打开/关闭节点页多次，事件、计时器、模型及图像租约不累积。

## 4. 最终面向使用者的交付

1. 节点模块及宿主注册入口。
2. 原生配置页面和结果查看入口。
3. 明确版本化的配置/资产示例，不含私有生产信息。
4. 一张图一次执行的最小接入示例，另附工作流循环示例。
5. 输入输出、状态、资源所有权、取消和错误处理说明。
6. 支持范围及限制：文字布局、码质量范围、参考对齐、ROI形状、输入布局/尺寸。
7. 已运行的回归清单、部署依赖及许可证/模型分发注意事项。

## 5. 不在此次封装中悄悄扩大承诺

- 不宣称工业漏检率、真实相机吞吐或ISO码等级已验收。
- 不增加自动纠错期望文本、不放松必需检查、不将空结果当成功。
- 不把框架节点恢复到Vision层，不复制旧厂商标签程序集或添加类型转发。
- 不将当前仅矩形/受限平移的标签检测标成已支持任意Region和姿态跟随。
- 不覆盖历史发布包；节点完成后单独生成新的交付物。
