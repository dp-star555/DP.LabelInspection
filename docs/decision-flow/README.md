本版按用户明确的ROI处理规则修正。**旧版“整个任务首错即停”、统一先做图像质量的三张流程图已撤回，移入 `archive-v1/`，不得继续作为设计依据。** 本页ROI业务顺序已接入内置后端；分割/配对、文字质量、读码/码质量及ONNX识别已下沉，见[迁移记录](../../../../DP.Vision/ALGORITHM_MIGRATION.md)和[当前源码流程及兼容边界](../../CURRENT_INSPECTION_FLOW.md)。尚未重新绘制交互图。

这里的“质量检测”指**印刷外观质量**，不是把清晰度/对比度检查强行放到所有ROI前面。当前代码仍见 [源码现状](../../CURRENT_INSPECTION_FLOW.md)；已检查 `InspectionEngine.Inspect`，其先执行后端、再检查能力及绑定的实现尚不符合本版要求。

可替换算法的职责、接口位置和输入输出约束见[接口隔离方案](INTERFACE_ISOLATION.md)。后续实现按接口装配算法，不在ROI流程中写死分割、文字质检或码质检实现。

## 1. 主处理单位是ROI

按配置遍历ROI。每个ROI独立确定检查项目、校验条件、完成数据及质量检查，并生成该ROI结果。

- 单个ROI条件不满足、读取失败或引导值不匹配：该ROI直接NG，不继续该ROI后面的质检；保存结果后继续下一个ROI。
- 质量算法已执行并发现缺陷：该ROI可以有多个细节NG，不能为了“首错即停”只保留第一个错字或异常点。
- 遍历结束输出每个ROI的结果。若需要总判定，任一必检ROI为NG则整体NG，但不因此遗漏其他ROI结果。
- 共享图像根本不存在等任务级故障与ROI内故障不同，不能凭空声称完成了检测；具体任务级异常协议另行定义。

## 2. ROI类型与检查能力

| ROI类型 | 可配置项目 | 质量检查必需条件 | 数据读取必需条件 |
|---|---|---|---|
| 固定 | 默认质量检查，不作为数据类ROI | 固定区域质检算法及它需要的参考/参数 | 不适用 |
| 空白 | 默认质量检查，不作为数据类ROI | 空白区域质检算法及参数 | 不适用 |
| 可变字/文字 | 质量、数据，或两者 | 字符分割/配对能力，加上字库比对或深度质检能力；需要OCR辅助身份时也必须具备OCR | OCR能力及所需模型/参数 |
| 条码 | 质量、数据，或两者 | 对应条码类型的独立质检能力及输入 | 对应条码类型的读码能力 |
| 二维码 | 质量、数据，或两者 | 对应二维码类型的独立质检能力及输入 | 对应二维码类型的读码能力 |

“独立”指功能与判定职责独立，不强制要求不同进程或不同供应商。能读码不代表能做码的印刷质检；有OCR或一个深度模型也不代表拥有完整的文字质检链。

深度方案也须明确它如何提供所需分割、配对和质量判定能力。不能未经确认就假设“有深度模型，可以省略全部分割和配对”。

## 3. 单个ROI的准确顺序

1. **取配置**：ROI类型，是否检查质量，是否读取数据，是否配置引导值，以及选择的算法和资源。
2. **检查已知条件**：先确认本ROI所有选中项目及其必要依赖都能执行。缺算法、模型、字库、分割能力或已知必需输入，直接生成本ROI的NG原因；不深入算法，继续下一个ROI。
3. **按需读取数据**：文字走OCR，码走对应读码算法。配置数据读取，或需要核对引导值时，必须取得真实读数；失败则本ROI NG。
4. **按需核对引导值**：有引导值则将真实读取值与其比较。不相等直接本ROI NG，不执行后续质量检测；相等才继续。未配置引导值时不做相等比较，不能把“没配引导值”一概当成缺输入。
5. **按需质量检测**：没选择质量就不运行质量专用算法；选择质量则按ROI类型运行相应质检。文字在此完成必要的分割、身份/参考配对及质量判定。只有运行后才能确定的条件，如实际字符分割失败、对应字符缺参考，也在发现时立即记本ROI NG。
6. **保存本ROI结果，继续下一个ROI**：质量结果可以包含多个字、多个异常点；保留实际读数、引导值比较结果以及已取得的完整证据。

配置引导值就产生“必须读取并比较真实内容”的需求。若界面同时明确禁止数据读取，这是配置冲突，不能静默忽略引导值。是否在编辑器自动联动开启读取，属于后续UI决定。

## 4. 执行逻辑（伪代码，非SDK实现）

```text
for 每个配置的检测ROI:
    解析 类型、质量项目、数据项目、引导值、算法资源
    建立本ROI所需能力和输入清单

    if 已知必需条件不满足:
        保存本ROI NG和条件缺失原因
        continue  # 下一个ROI，不是结束整个任务

    if 要求数据读取或配置了引导值:
        实际数据 = OCR或读码
        if 读取失败:
            保存本ROI NG和读取失败原因
            continue

        if 配置了引导值 and 实际数据 != 引导值:
            保存本ROI NG、实际值、引导值及可确定的不一致细节
            continue  # 本ROI质检未执行

    if 选择了质量检测:
        准备本类型质检所需的动态条件
        # 文字：必要分割、身份确定、参考/模型配对等
        # 可复用本ROI已经取得且确实适用的OCR/结构信息
        if 动态条件不满足:
            保存本ROI NG及阻断原因
            continue

        执行相应质量检测
        保存质量判定及全部已取得的细节NG

    保存本ROI完整结果

返回全部ROI结果
```

## 5. 文字质量与数据的交集

数据项目关心“读出了什么，是否与引导值一致”；质量项目关心“字形印刷是否完整、是否存在异常”。两者可能共用OCR、字符位置或身份信息，但不能互相代替。

- **数据+质量+引导值**：先OCR，再与引导值比较；一致后才深入分割、配对、质量检测。质量阶段可复用已有OCR证据，不无理由再识别一次。
- **只做文字质量**：不强制要求业务数据比较；但选定质检方案若依赖OCR确定字形身份，OCR仍是必要依赖，缺失则NG。
- **只做文字数据**：OCR以及可选的引导值比较完成后结束本ROI，不运行质量专用分割/配对/像素比较。
- OCR本身若需要文本定位、内部切分等步骤，它们属于读取的必要前置，不等于提前启动了完整印刷质检。
- OCR正确不代表没有缺笔；字形相似或质量模型通过也不能冒充数据读取成功。
- 保留原始读取结果，不用引导值悄悄纠正OCR读数后再宣称一致。

## 6. ROI结果与细节

每个ROI一个结果，包含：类型、综合OK/NG、数据读取状态及原始值、引导值及比较结果、质量状态、原因列表、已获得证据和细节NG列表。

| 情况 | 记录方式 |
|---|---|
| 没有选择数据或质量项目 | 对应项目记“未配置/不适用”，不是完成通过 |
| 数据读取成功但没有引导值 | 保存实际读数；引导值比较记“未配置” |
| 数据不一致导致质量没运行 | ROI NG；质量记“未执行：数据不一致” |
| 缺字符分割或字库等 | ROI NG；记录比较阻断原因，不伪造局部印刷缺陷 |
| 质量发现多个异常 | 一个ROI NG，可有多个字符或区域级NG子项 |
| 没有可靠字符位置或差异配对 | 保留文本差异，不编造第几个字符的图像缺陷框 |
| 全部已选择项目完成且合格 | ROI OK |

固定/空白不应配置成数据读取ROI；检测ROI没有任何有效项目也不能空跑后默认OK。显式忽略区域不是一个已通过的检测项目。

示例：ROI1引导值不一致 → ROI1 NG、质检未执行；ROI2质检发现3处异常 → ROI2 NG、3条质量细节；ROI3所有选中项目合格 → ROI3 OK。最终返回三个ROI结果，不在ROI1处结束遍历。
