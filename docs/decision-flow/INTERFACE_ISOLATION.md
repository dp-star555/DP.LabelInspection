# 可替换算法的接口隔离方案

> 当前实现及准确边界以 [迁移记录](../../../../DP.Vision/ALGORITHM_MIGRATION.md) 为准：分割/配对、单字及整段质量、读码/码质量和ONNX识别已接入；下文保留原设计讨论，不代表HALCON等规划能力已实现。

前提：遵循[ROI驱动流程](README.md)。每个ROI独立完成条件检查、必要的数据读取及引导值比较、质量检查和结果输出；本ROI提前NG不终止后续ROI。

本文件是总体设计约束。首批中立单字比较、固定/空白接口及OpenCV实现已接入，QR检查器已可单独注入；原公开入口保留。其他拟议接口与完整ROI编排仍未落地，见[迁移记录](../../../../DP.Vision/ALGORITHM_MIGRATION.md)。

## 工程归属补充

通用分割、OCR、字形外观、码读取/质检、匹配等视觉契约及实现下沉到DP.Vision工程族；本文件中的接口方向不是要求全部定义在标签项目中。中立契约按能力类型组织，具体实现按OpenCV/HALCON等基座提供。标签项目保留ROI规则、引导值、字库业务绑定和判定汇总。详见 [DP.Vision算法工程族方案](../../../../DP.Vision/ALGORITHM_MODULES.md)。

## 1. 两层职责必须分开

**ROI流程模块**负责遍历ROI、解析所选项目、检查能力与资源、决定调用顺序、比较实际值和引导值、停止当前ROI的后续步骤、保留各阶段结果并汇总ROI判定。

**算法模块**负责一个可替换的算法职责，接收明确输入，返回明确的执行状态、数据/质量结果及证据。不操作UI、不遍历其他ROI、不擅自改变配置，也不自行决定整个任务是否结束。

质量算法可以根据自身配置判定质量是否合格；流程模块不强行把不同算法的分数或阈值解释成同一种尺度。

## 2. 接口隔离位置

| 职责 | 接口方向 | 说明 |
|---|---|---|
| 文字数据读取 | 保留现有 `ITextLineRecognizer`；需要非CTC实现时增加中立的 `ITextReader`，用适配器接入现有OCR | 实际文字、可靠性、可用位置证据；CTC信息作为实现特有的可选证据，不能要求所有OCR都提供CTC |
| 码数据读取 | 复用现有 `IBarcodeDecoder`，按支持码制选择实现 | 条码和QR可由同一读码实现支持；是否能读取某码制须明确声明，不代表具备其质检能力 |
| 字符分割 | 复用/兼容演进 `ICharacterSegmenter` | 提供实际字符字块及几何证据、分割状态；不能靠OCR字符数强行等分 |
| 字符配对 | 拟议 `ICharacterMatcher` | 实际字块与字符身份、固定版本参考之间的对应关系；明确缺字、歧义及无法配对 |
| 单字比较 | 复用 `IGlyphComparer` | 传统像素/形状比较的细粒度替换位置；不同实现保留各自指标和阈值含义 |
| 文字质量检查 | 拟议 `ITextQualityInspector` | ROI流程调用的完整文字质检接口；传统实现组合分割、配对、单字比较，也可由具备相应能力的深度实现替换 |
| 一维条码质量 | 拟议 `ILinearBarcodeQualityInspector` | 独立选择、注入条码质检实现，不混入业务内容比较 |
| QR质量 | 拟议 `IQrQualityInspector` | 独立选择、注入QR质检实现；不得在一维条码质检内部写死创建QR实现 |
| 固定区质量 | 拟议 `IFixedQualityInspector` | 固定区域参考比对的可替换实现 |
| 空白区质量 | 拟议 `IBlankQualityInspector` | 空白异常检测的可替换实现 |

接口名暂定，优先兼容现有契约，不为了命名统一破坏已有使用方。外部调用者仍只需要检测引擎入口，不需要亲自拼接每一个内部步骤。

分割、配对、单字比较是文字质量模块内的细粒度替换位置；文字质量接口是完整方案的替换位置。深度方案并不天然具备所有这些能力，也不强制拆成多次模型推理：必须说明所需分割/配对如何完成，缺能力则本ROI NG，不能靠“已配置深度模型”默认通过。

不把二值化、形态学等每一个内部算子都公开成接口，也不建立一个靠字符串命令和object参数执行所有算法的万能接口。

## 3. 每个接口不止规定方法名

每个可选算法实现需要明确以下契约：

1. **身份与适用范围**：实现标识、版本、支持的ROI/码制、输入限制及参数版本。
2. **前置需求**：所需模型、参考库、分割/配对能力、是否需要OCR身份、解码结构或其他证据。需求可以随所选算法与配置改变，不能只靠一个全局能力标志判断。
3. **配置验证**：在运行昂贵算法前验证已知配置、参数和资源；返回具体缺失原因。检查成功不承诺运行一定成功，运行时仍须检查实际结果。
4. **中立输入**：图像、ROI、所需参数、固定版本参考及可选的已完成证据。公开契约不出现Mat、HObject、ONNX张量、UI控件或数据库连接。
5. **明确输出**：执行完成/不支持/前置不足/失败，与质量合格/不合格分开；包含实际数据、质量指标、局部缺陷及阻断原因。
6. **证据归属**：缺陷及字符几何使用约定的原图坐标；原始图像不可改写。调用中借用的像素与返回后仍有效的证据必须有明确生命周期，不能留下已释放原生内存引用。
7. **取消与并发**：声明是否可并发复用；不默认共享模型线程安全。宿主明确负责创建和释放，调用方传入取消信号；取消不吞成OK。

不得用“返回空缺陷列表”表示检测成功：空列表可能是干净，也可能是没执行或不支持。ROI流程必须依据明确的完成状态判定。

若模型只输出ROI级NG，没有真实的局部证据，应诚实返回ROI级NG；不得为了统一界面编造错字或异常点。

## 4. 文字与OCR共享证据，但不混合判定

- 先读取并核对引导值；不一致则不调用后续文字质量接口。
- 已获得的OCR文字、位置及可靠性信息，可以作为只读证据传给文字质检。
- 配对模块只能使用实际可用证据；CTC激活位置不能直接当成物理字符边界。
- 只选文字质量时，若所选实现需要OCR，流程根据其需求安排必要OCR；没有业务数据项目并不禁止内部身份读取。
- 证据复用限定同一任务/图像、同一ROI及有效配置；不同来源、变换或模型的结果不能无条件混用。引导值与实际读数保留各自身份。
- OCR已被证明适用时无需重复运行；不适用时必须说明额外处理的原因，不能暗中覆盖首次实际读数。

## 5. 选择与装配

配方指定检查项目、算法标识和对应参数/参考版本；宿主提供实现及生命周期。装配模块按所选实现建立所需依赖，ROI流程只调用接口。

缺少配置的算法或版本，不自动换一个“差不多”的实现；本ROI NG并给出原因。若以后需要后备方案，必须显式配置允许的顺序、适用条件及证据记录。

替换传统算法为深度算法不意味着指标、阈值或准确率等价。配置必须匹配具体实现并重新验证，不能照搬旧阈值后宣称效果不变。

## 6. 当前代码取证与差距

- `Contracts/CharacterServices.cs` 已有 `ICharacterSegmenter` 和 `IGlyphComparer`。现有分割接口同时接受文字并产生身份关联；若要独立替换纯分割和配对，需要兼容适配，而不是直接删除旧签名。
- `OpenCvInspectionBackend` 已支持注入上述接口及 `IBarcodePrintInspector`，但其大后端仍承担大量流程职责。
- `OpenCvBarcodePrintInspector.Inspect` 原来在发现QR时直接 `new OpenCvQrPrintInspector()`；首批已改为构造注入QR检查器。后续批次已迁入中立码质检契约，一维码和QR分别可替换。
- `TextAppearanceInspection.Run` 同时执行OCR、内容规则、分割、字库加载和比较，须按读取/业务比较/文字质量职责拆开。
- 现有 `IBarcodePrintInspector` 只返回缺陷列表，不能独立证明执行完整性；后续通过兼容适配演进为明确的执行与质量结果。

## 7. 后续实施验收条件

- 更换分割、配对或质检实现，不需要修改ROI遍历、UI或引导值比较逻辑。
- 未选择质量项目且没有其他需求时，质量专用模块调用次数为零。
- 本ROI缺少必需条件时，不调用该ROI昂贵算法；下一ROI仍执行。
- 读取失败或引导值不一致时，该ROI质量模块调用次数为零。
- 条码读取通过但质量失败，仍返回该ROI NG；不能以读码结果代替质量结果。
- 替换QR质检不会改变一维条码质检的选择，也不会隐式回退。
- 文字质量可以保留多个缺陷子项，条件不足仅返回阻断原因，不伪造缺陷。
- 使用可计数的测试实现验证调度顺序与未调用行为；真实算法另外验证证据、模型/参数适配和资源释放。替换测试不等于工业精度验证。
